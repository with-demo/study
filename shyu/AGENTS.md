# 책이음 전용 작업 규칙

이 문서는 `with-demo/study` 저장소의 `shyu/` 작업에 적용한다.
저장소 최상위 `AGENTS.md`의 팀 공통 규칙을 함께 따른다. 사용자의 명시적 요청이 우선한다.

## 작업 시작과 수정 범위

- 작업 전 최상위 `AGENTS.md`, 이 문서, `shyu/README.md`와 관련 최신 소스를 읽는다.
- 현재 브랜치, 로컬 변경사항, 원격 변경사항을 확인한다. 최신화할 때 기존 작업을 덮어쓰거나 초기화하지 않는다.
- 요청한 파일과 직접 영향을 받는 범위만 수정한다. 다른 저장소는 조회하거나 수정하지 않는다.
- 다른 팀원 폴더, `common/`, 루트 `index.html` 및 최상위 `AGENTS.md`는 별도 요청 없이 변경하지 않는다.
- 공통 기획 도구는 기존 상대 경로로 참조하고 `shyu/` 안에 복제하지 않는다.

## 기획 기준

- 서비스명은 **책이음**, 슬로건은 **읽는 즐거움에서, 함께하는 즐거움으로**이다.
- 서울의 도서관·독립서점·문화공간에서 열리는 독서 프로그램을 탐색하고 신청하는 성인 대상 사용자용 서비스이다.
- 프로그램 유형은 **독서모임 / 글쓰기 / 북토크·강연 / 독서 체험**이다. 공간 유형과 프로그램 유형을 구분한다.
- 아래 Google Sheets의 **개요**는 서비스 목적·대상·범위의 기준, **최종 사이트맵**은 메뉴·화면·기능 구성의 기준으로 사용한다.
  - 개요: https://docs.google.com/spreadsheets/d/1PJXecupGoHac33HbqTSw_coDpm796iJdwWz8VnaGvcQ/edit?gid=241124001
  - 최종 사이트맵: https://docs.google.com/spreadsheets/d/1PJXecupGoHac33HbqTSw_coDpm796iJdwWz8VnaGvcQ/edit?gid=241125001
- 기존 목업에 맞춰 기획을 임의로 바꾸지 않고, 확정한 기획에 맞춰 화면을 수정한다.
- 기준 문서가 충돌하거나 정책이 미정이면 임의로 확정하지 않고 사용자에게 알린다. 접근할 수 없는 자료를 읽었다고 말하지 않는다.
- Google Sheets는 사용자가 요청한 시트와 범위만 수정한다.

## 디자인과 기능 보존

- 관리자 화면이 아닌 일반 사용자가 프로그램을 찾고 신청하는 화면으로 구성한다.
- 은은한 연두색과 짙은 초록색의 브랜드 방향을 유지한다.
- 사진·포스터 중심으로 탐색하게 하고, 과도한 테두리·박스·반복 정보를 줄인다.
- 제목·본문·보조 정보의 위계, 정렬·여백·글꼴·버튼을 일관되게 적용한다. 본문은 읽기 쉽게, 주요 문구는 기존 명조체 방향을 적절히 활용한다.
- 메인과 목록·상세·신청·마이페이지, 헤더·푸터에 같은 디자인 기준을 적용한다.
- 참고 화면의 정보 위계와 배치 원리를 참고하되 그대로 복제하지 않는다.
- 국내 독립서점·도서관·성인 독서 문화에 어울리는 이미지를 사용하고, `assets/images/SOURCES.md`의 출처를 유지한다.
- 디자인만 요청받은 경우 기존 메뉴·기능·사용자 흐름·입력 검증·화면 ID를 임의로 바꾸지 않는다.
- 기능 변경 시 연결된 메뉴·화면 이동·팝업·알럿/컨펌·Description도 함께 확인한다. 기존 ID와 이전 링크 호환을 보존한다.

## 서비스 동작과 구현 범위

- 탐색 → 상세 확인 → 신청서 작성 → 신청 완료 → 나의 예약 확인 흐름을 유지한다. 비로그인 상태에서 신청하면 로그인 후 해당 신청서로 복귀한다.
- 접수 상태, 진행 상태, 행사 날짜 검색은 서로 구분한다. 다회차 프로그램은 실제 개최일마다 캘린더에 표시한다.
- 상세 접근·예약 취소·후기 작성 등 조건은 최신 최종 사이트맵과 승인된 정책을 따른다. 일반적인 관행을 이유로 임의 변경하지 않는다.
- 찜하기·찜 해제와 마이페이지의 찜 목록을 연결한다.
- 지도는 현재 Leaflet + OpenStreetMap 구조와 출처 표기를 유지한다. 사용자용 화면에 API 연결 설정 버튼을 넣지 않는다.
- 프로그램 이용자용 로그인과 공통 도구의 GitHub 공동작업자 로그인을 구분한다.
- 현재 브라우저 저장소와 예시 데이터 기반 목업이라는 구현 경계를 유지한다. 실제 인증·기관 예약·결제·메일 발송을 구현했다고 안내하지 않는다.
- 실제 개인정보·계정 비밀번호·API 키를 소스나 예시 데이터에 넣지 않는다. 예시 공간·사진·주소·좌표를 실제 기관 정보라고 단정하지 않는다.
- 실습·목업·개발 과정 설명은 사용자 화면에 노출하지 않는다. 공통 기획 도구는 유지하고, 구현 제한사항은 `shyu/README.md`에서 관리한다.

## 문서와 정책 변경 기록

- `AGENTS.md`는 작업 방법, Google Sheets는 기획 내용, `shyu/README.md`는 실행 방법·파일 구성·작업 설명·구현 제한사항을 관리한다.
- 사용자가 승인하거나 명시적으로 요청한 서비스 정책 변경만 확정 사항으로 기록한다.
- 정책 변경 시 기존 내용을 보존하고 `→ [yy.mm.dd 변경] 변경된 내용` 형식으로 추가한다. 해당 정책을 관리하는 문서의 변경 이력에 날짜와 이유를 기록한다.
- 단순 위치·색상·배치 변경이나 정책과 무관한 문구 수정은 정책 변경 이력에 포함하지 않는다.
- 기존 문서를 임의로 전면 재작성하지 않는다. 별도 디자인·레이아웃 문서가 존재한다고 가정하거나 요청 없이 새로 만들지 않는다.

## 저장·검증·완료 보고

- 코드 수정과 커밋은 작업 브랜치에서 진행한다. 기존 작업 브랜치 `codex/shyu-bookieum-consumer-ui`를 이어 쓸 때는 병합 이력과 최신 `main`과의 관계부터 확인한다.
- `main` 병합과 공개 배포는 명시적으로 요청받았을 때만 진행한다. 이전 배포 승인을 이후 작업의 상시 승인으로 해석하지 않는다.
- 커밋·PR은 한국어로 작성하고 실제 작업자 계정과 기존 이력을 유지한다. 관련 없는 변경을 포함하지 않는다.
- 변경 범위에 맞춰 화면 표시·반응형 배치·리소스 경로·화면 이동·관련 기능을 검증한다.
- 신청·예약·후기 변경은 필수값·입력 형식·중복 처리·상태 조건·오류 및 취소 경로도 확인한다. 지도 변경은 로컬 미리보기와 공개 환경 차이를 고려한다.
- 완료 시 변경 내용, 검증 결과, 미확인 사항을 알린다. 로컬 저장 / 커밋 / push / main 병합 / 공개 배포 여부를 구분한다.
- 커밋·PR·배포를 진행했다면 확인 가능한 링크를 제공한다. 확인하지 않은 상태를 완료했다고 보고하지 않는다.
