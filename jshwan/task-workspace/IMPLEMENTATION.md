# 기능과 구현 기준

기준: 제공된 Task 사이트맵·기능 명세 v0.2 (2026-11-26). 문서의 기능 요구사항을 구현 기준으로 사용했습니다.

|명세|구현 위치 / 동작|
|---|---|
|F01–02 로그인·작업 공간|Sites ChatGPT 인증, 계정별 단일 D1 행. 인증 없는 API는 401. 재로그인 시 기존 공간 사용.|
|F03–05 홈|오늘·기한 초과·진행 중 요약, 오늘 작업 완료, 프로젝트 완료율.|
|F06–12 내 작업|추가·편집·복제·삭제·완료·다시 열기, 목록·드래그 보드, 필터·정렬·일괄 변경, 오늘/예정/완료 보기.|
|F13–16 프로젝트|생성·수정·개요·목표일·상태·소속 작업·목록·보드.|
|F17–18 캘린더|월 이동, 날짜별 일정, 프로젝트·완료 필터, 선택 날짜 작업 추가, 상세에서 마감일 변경.|
|F19–21 보관·휴지통|프로젝트 보관, 삭제·복원·확인 후 영구 삭제. 프로젝트와 함께 삭제된 작업만 연쇄 복원.|
|F22–23 설정|계정, 현재 기기 로그아웃, 공간 이름·시작 화면·주 시작 요일 서버 저장.|
|F24–25 백업|JSON 다운로드, 최대 3MB 형식·날짜·상태·관계·중복 ID 검증, 확인 후 전체 대체.|
|F26–29 공통|통합 검색·Ctrl K, 빠른 추가, 우측 상세·체크리스트, 모바일 메뉴·전체 상세.|

## 결정한 정책

- 한국 시간(Asia/Seoul)으로 오늘과 지연을 판정합니다.
- 계정별 작업 공간 문서를 D1에 저장하고, 전체 문서의 버전으로 조건부 업데이트합니다. 충돌은 409를 반환하며 기존 입력을 유지합니다. 최신 목록을 확인하고 명시적으로 다시 저장해야 합니다.
- 필드 편집은 ‘저장’ 버튼으로 확정합니다. 완료 전환·보드 이동·일괄 변경 등 즉시 동작은 서버 응답 후 화면에 반영합니다. 서버 응답 전에는 저장 완료로 표시하지 않습니다.
- 일괄 변경은 전부 성공하거나 전부 취소됩니다. 일부 작업이 없으면 오류를 보여줍니다.
- 프로젝트를 삭제할 때 이미 휴지통에 있던 작업은 프로젝트 복원으로 되살리지 않습니다. 프로젝트가 삭제된 상태에서는 소속 작업만 먼저 복원할 수 없습니다.
- 백업은 병합하지 않고 전체 대체합니다. ID는 서버에서 다시 발급하고 관계를 재연결합니다. 소유자 식별자는 요청으로 받지 않으며 인증된 사용자에서 결정합니다.
- 기본 예시 데이터는 없습니다. 팀 협업, 반복 작업, 알림, 외부 연동은 명세의 후속 범위입니다.
- 인증 헤더의 신뢰 경계는 Sites의 인증 게이트웨이입니다. 다른 환경에 직접 노출할 경우 해당 인증을 별도로 구성해야 합니다.

## 확인 명령

```sh
node --test tests/domain.test.mjs
npx tsc --noEmit
npm run build
```

로컬 개발 인증과 데이터베이스는 실제 서비스 계정·데이터와 분리됩니다. 서비스 동작 확인은 배포된 주소에서 본인 계정으로 로그인해 진행합니다.
